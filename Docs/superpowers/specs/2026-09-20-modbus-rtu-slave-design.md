# Modbus RTU 从机设计

## 目标

将已经验证可用的 USART1 RS485 硬件接入平台化软件架构，关闭临时调试死循环，增加一个独立 FreeRTOS Modbus RTU 从机线程。RS485 方向控制保持现有语义：PA12 低电平接收、高电平发送，发送完成后回到低电平。

## 协议参数

- 从机地址：`1`
- 波特率：`115200`
- 数据格式：`8N1`
- 传输模式：Modbus RTU
- 最大 ADU：256 字节
- 支持功能码：`0x03`、`0x06`、`0x10`
- 广播地址 `0`：执行写操作但不回复

## 软件边界

### RS485 UART 服务

`Services/Src/rs485_uart.c` 只负责 USART1 接收空闲分帧、帧队列和发送方向控制。接收使用 HAL 的 `ReceiveToIdle_IT`，协议解析不在中断里执行。发送接口在发送前将 PA12 置高，阻塞等待 HAL 发送完成，再将 PA12 置低。

### Modbus 协议服务

`Services/Src/modbus_rtu.c` 实现 CRC16、地址过滤、长度校验、功能码解析、异常响应和响应帧生成。寄存器读写通过 `modbus_register_map` 接口完成，协议服务不直接依赖具体传感器。

### 寄存器映射

| 地址 | 访问 | 含义 |
| --- | --- | --- |
| `0x0000` | R | 设备状态：bit0 IMU ready，bit1 AD7606 ready，bit2 最近一次 IMU 读取成功，bit3 最近一次 AD7606 读取成功 |
| `0x0001` | R | 8 路数字输入位图 |
| `0x0002` | R/W | 数字输出位图 |
| `0x0010..0x0017` | R | AD7606 8 路有符号原始值，按 uint16 原样传输 |
| `0x0020..0x0025` | R | IMU 原始值：加速度 X/Y/Z、陀螺仪 X/Y/Z |
| `0x0030..0x0032` | R | 姿态 Roll/Pitch/Yaw，单位 `0.01 deg`，有符号整数 |

### Modbus 线程

`Application/Src/Task_modbus_rtu.c` 是唯一处理 Modbus 请求的线程。线程从 RS485 帧队列取完整帧，调用协议服务生成响应，再通过 RS485 UART 服务发送。线程不使用 `printf` 输出到 RS485，避免调试日志污染协议总线。

## 错误处理

- CRC 错误、地址不匹配、帧长度错误：丢弃且不回复。
- 不支持的功能码：异常码 `0x01`。
- 寄存器地址不存在：异常码 `0x02`。
- 写入值或数量非法：异常码 `0x03`。
- 内部服务不可用：异常码 `0x04`。
- 响应帧超过 256 字节：返回设备故障异常，不发送超长帧。

## 启动路径

关闭 `APP_RS485_DEBUG_ONLY` 后，主函数进入原有 HAL + FreeRTOS 路径。`MX_FREERTOS_Init` 通过现有任务注册入口创建 Modbus 线程。现有 PA12 方向定义和 USART1 TX/RX swap 配置保留，不改硬件收发方向。

## 验证标准

- 静态检查确认调试死循环不再作为启动入口。
- 静态检查确认发送路径严格为“PA12 高 -> USART1 发送完成 -> PA12 低”。
- 协议向量检查覆盖正常 CRC、错误 CRC、地址过滤、广播写、`0x03`、`0x06`、`0x10` 和异常响应。
- 不运行 Keil/GCC 编译，按用户要求由用户自行编译下载。
