# 数字输入鉴频与16模式IO程序设计

## 1. 目标

将八路隔离数字输入固定划分为以下产品功能：

| 通道 | 产品功能 | 输出数据 |
|---|---|---|
| DI1～DI2 | 高速脉冲计数、频率测量及软件鉴频 | 64位累计计数、频率、鉴频状态 |
| DI3～DI6 | 4位并行模式选择输入 | 选择上位机编写并下载的0～15号IOCF程序 |
| DI7～DI8 | 普通开关量输入 | 消抖状态，可作为当前模式程序的条件 |

DI3～DI6不是固定输出码，也不依赖上位机实时控制。上位机负责为模式0～15编写16套IOCF程序并通过Modbus下载；MCU负责掉电保存、读取模式输入、自动切换程序和独立执行。通信断开或设备重新上电后，已下载程序继续有效。

原DI6～DI8增量编码器A/B/Z功能退出当前产品定义，相关运行代码、数据字段和寄存器定义一并移除，避免一个物理通道同时承担两种产品语义。

## 2. 高速脉冲鉴频

### 2.1 采集与频率计算

- DI1继续使用PE9/TIM1_CH1外部时钟计数。
- DI2继续使用PB7/TIM4_CH2外部时钟计数。
- 光耦输出下降沿为有效计数边沿。
- 硬件16位计数器由1 ms数字IO任务扩展为64位累计计数。
- 频率按100 ms窗口计算，单位Hz，分辨率10 Hz。
- 产品保证范围为0～2 kHz；超过2 kHz时只报告超量程，不保证计数和频率精度。

### 2.2 鉴频状态

每路输出独立状态：

| 状态 | 含义 |
|---|---|
| `NO_SIGNAL` | 达到无脉冲超时，未检测到连续输入信号 |
| `BELOW_LIMIT` | 有脉冲，但频率低于应用下限 |
| `IN_RANGE` | 频率位于应用下限和上限之间 |
| `ABOVE_LIMIT` | 频率高于应用上限，但未超过2 kHz硬件保证范围 |
| `OVER_RANGE` | 频率超过2 kHz硬件保证范围 |

每路使用独立配置：下限频率、上限频率、迟滞频率、无脉冲超时和连续确认窗口数。正式默认值如下：

| 参数 | 默认值 |
|---|---:|
| 下限频率 | 10 Hz |
| 上限频率 | 1800 Hz |
| 超量程门限 | 2000 Hz |
| 迟滞 | 10 Hz |
| 无脉冲超时 | 1000 ms |
| 状态确认 | 连续3个100 ms窗口 |

状态切换必须同时满足迟滞和连续确认条件，防止频率在阈值附近波动时反复报警。累计脉冲数不受鉴频状态影响。

鉴频状态作为IOCF运行输入，上位机可编写例如“无流量关闭泵”“超速断开继电器”“正常频率打开指示输出”等控制规则。

## 3. 四位模式选择输入

### 3.1 位定义

DI3～DI6组成一个4位无符号模式码：

| 输入 | 权值 | 模式码位 |
|---|---:|---:|
| DI3 | 1 | bit0 |
| DI4 | 2 | bit1 |
| DI5 | 4 | bit2 |
| DI6 | 8 | bit3 |

计算式为：

`mode = DI3 + 2*DI4 + 4*DI5 + 8*DI6`

全部无效时模式为0，全部有效时模式为15。每个模式号对应程序包中的一套独立IOCF控制程序。

### 3.2 稳定判定

- 1 ms读取一次四位原始模式码。
- 原始模式码连续20 ms保持不变后才确认为新的稳定模式。
- 稳定期间出现任意位变化，20 ms计时重新开始。
- 只有稳定模式发生变化时才增加模式切换计数并更新时间戳。
- 上电后的首个模式同样经过20 ms确认，不直接采用瞬时GPIO状态。

该整组判定用于抑制外部继电器、拨码开关或PLC多路输出切换不同步产生的过渡码。当前硬件没有独立选通信号，因此不承诺无延时的原子并行采样。

## 4. 16模式IOCF程序包

上位机为模式0～15分别创建IOCF程序。每套程序可独立使用DI7、DI8普通输入条件和DI1、DI2鉴频状态，并控制4路继电器与4路晶体管输出；支持置位、复位、翻转、定时脉冲、延时和联锁。未配置模式必须标记为空模式，选中后全部输出保持关闭。

每套模式是按10 ms周期持续执行的动态控制程序，不是固定的输出掩码。模式被选中后，IO逻辑引擎持续读取DI1、DI2的脉冲/鉴频状态和DI7、DI8的开关状态；输入条件、定时条件或内部规则状态变化时，程序可自动改变8路输出，不需要上位机保持在线或逐次发送输出命令。DI3～DI6只承担模式选择职责，不作为当前模式内部的普通条件输入，防止模式选择与模式逻辑形成循环依赖。

新增模式程序包格式`IOPB`，格式版本为2。程序包包含固定包头、16项模式目录、鉴频公共参数以及0～16个IOCF程序体。每套IOCF最多32条规则、最大4096字节，整包不得超过单个128 KiB Flash槽容量。

下载继续使用Modbus自定义功能码`0x41`的BEGIN、DATA、VERIFY、ACTIVATE事务。Flash A/B双槽分别保存一份完整IOPB包；下载只写非活动槽，整包CRC32和各模式CRC32全部通过后才写入有效标记并原子切换。下载失败、校验错误或中途掉电不得破坏原有效程序包。

稳定模式变化时，MCU依次关闭全部输出、停止旧程序、清除旧程序的延时/脉冲/边沿状态、校验并装载目标程序。切换至少保留一个IO逻辑扫描周期的全关间隔，防止两套模式输出重叠。模式切换不写Flash。

## 5. 普通开关量输入

DI7～DI8作为独立普通开关量输入，1 ms采样，连续5次一致后更新状态，典型消抖时间5 ms。其状态继续合并到八路输入总掩码中。

## 6. 软件结构

- `BSP/Src/bsp_pulse_counter.c`：只负责DI1、DI2硬件计数器。
- `Services/Src/digital_io_service.c`：负责计数扩展、频率计算、鉴频状态机、四位模式稳定判定及DI7～DI8消抖。
- `Services/Inc/digital_io_service.h`：定义鉴频配置、鉴频状态和完整输入快照。
- `Services/Src/io_config_storage.c`：负责IOPB双槽下载、校验、激活和模式目录访问。
- `Services/Src/io_logic_engine.c`：装载并执行当前模式的IOCF程序。
- `Services/Inc/datahub.h`：发布跨任务数字IO、鉴频和模式运行快照，不保留编码器字段。
- `Application/Src/Task_digital_io.c`：1 ms驱动服务，10 ms发布DataHub快照。
- `Application/Src/Task_io_logic.c`：处理模式切换并按10 ms周期执行活动IOCF程序。
- `Services/Src/modbus_register_map.c`：向上位机公开计数、频率、鉴频和模式运行数据。
- `BSP/Src/bsp_encoder_input.c`及其头文件退出正式工程和Keil工程文件。

数字输入服务只发布稳定模式，不直接切换输出；模式管理和规则执行属于IO逻辑服务，确保采集职责与业务控制职责分离。

## 7. Modbus寄存器

保留脉冲累计值和频率原地址，重新定义原编码器寄存器区域：

| 地址 | 数据 |
|---:|---|
| `0x0040～0x0043` | DI1的64位累计脉冲数，高字在前 |
| `0x0044～0x0047` | DI2的64位累计脉冲数，高字在前 |
| `0x0048～0x0049` | DI1频率，32位Hz |
| `0x004A～0x004B` | DI2频率，32位Hz |
| `0x004C` | DI1鉴频状态 |
| `0x004D` | DI2鉴频状态 |
| `0x004E` | DI3～DI6稳定模式号，范围0～15 |
| `0x004F` | DI3～DI6当前原始模式号，范围0～15 |
| `0x0050～0x0051` | 模式切换计数，32位 |
| `0x0052～0x0053` | 最近模式切换时间，32位ms |
| `0x0054` | DI7～DI8消抖后状态，保留原bit6～bit7位置 |
| `0x0055` | 模式状态：稳定、已配置、运行、切换故障标志 |
| `0x0056` | 服务状态：高速计数器就绪、程序包有效标志 |
| `0x0057` | DI3～DI8消抖/稳定后的低速输入状态 |
| `0x0058` | 当前模式程序规则数量 |
| `0x0059～0x005A` | 当前IOPB程序包代次，32位 |
| `0x005B` | IOPB有效模式位图，bit0～bit15对应模式0～15 |

本次只读寄存器变更属于协议版本变化，上位机需要同步更新字段名称和解析逻辑。

## 8. 应用示例

- 流量计：DI1接脉冲流量计，累计脉冲换算累计流量，频率换算瞬时流量；活动IOCF可在停流或超量程时关闭阀门并报警。
- 转速传感器：DI2接转速脉冲，频率换算转速；活动IOCF可根据停转、低速、正常和超速状态控制输出。
- PLC工艺选择：PLC四路数字输出连接DI3～DI6，在16套已下载的工艺程序之间切换。
- 本地模式指令器：四位拨码或编码开关连接DI3～DI6，在上位机离线时选择模式0～15。
- 限位与联锁：DI7～DI8接行程、门禁或压力开关，作为每套IOCF程序的输入条件。

## 9. 验证要求

1. 对DI1、DI2分别输入0、10、100、1000、1800、2000和高于2000 Hz信号，核对累计计数、频率和鉴频状态。
2. 在上下限附近往返扫频，确认迟滞及连续3窗口确认不会产生状态抖动。
3. 遍历DI3～DI6全部16种组合，确认模式号与位权一致。
4. 模拟四位输入不同步切换，确认仅在新组合稳定20 ms后切换一次。
5. 为16个模式下载不同规则，逐一核对程序与模式对应。
6. 检查切换时输出先全关，旧模式延时和脉冲状态不会进入新模式。
7. 在下载各阶段断电，确认旧程序包仍能启动；空模式和损坏模式保持输出关闭。
8. 验证DI7、DI8在触点抖动条件下只输出稳定状态。
9. 通过Modbus逐项读取`0x0040～0x005B`，核对数据宽度、字序和状态编码。
